# Google Meet 出席自動集計ツール

Google Meet で実施しているプログラムの出席管理を自動化する Google Apps Script です。

## 解決する課題

| 現状(手作業) | このツール導入後 |
| --- | --- |
| 講師が画面の参加者を目視で数えて手入力 | Meet が記録している参加者データを毎日自動取得 |
| 月次の集計が手作業 | 月次サマリーを自動生成 |
| リピート率の集計が手作業 | 新規/リピーター/リピート率を自動計算 |

Google Meet は会議ごとに「誰が・いつ入室し・いつ退出したか」を記録しており、
**Google Meet REST API** でその記録を取得できます。このスクリプトは毎日それを
スプレッドシートに取り込み、集計シートを更新します。**講師の操作は一切不要**になります。

## 生成されるシート

1. **参加ログ** — 1行 = 1人 × 1回の会議。日付・会議コード・参加者名・入退室時刻・滞在時間(分)
2. **月次サマリー** — 月ごとの 開催回数 / 延べ参加者数 / ユニーク参加者数 / 新規参加者数 / リピーター数 / **リピート率** / 平均参加者数
3. **参加者マスタ** — 参加者ごとの 初回参加日 / 最終参加日 / 参加回数 / 参加月数
4. **名前対応表** — Meet の表示名と本名の対応を管理(下記「参加者名を本名に置き換える」参照)

### リピート率の定義

> その月のユニーク参加者のうち、**それ以前の月にも参加したことがある人**の割合

(= リピーター数 ÷ ユニーク参加者数。定義を変えたい場合はご相談ください)

## 前提条件

- **会議を主催(作成)しているアカウント**でこのスクリプトを実行すること。
  Meet API は自分が主催した会議の参加者記録のみ取得できます。
- 無料の Google アカウントでも Google Workspace でも動作します。
  録画や文字起こしの取得には Workspace が必要ですが、本ツールが使う
  参加者記録(入退室時刻)の取得に Workspace は不要です。
- 参加者データは**会議終了後**に生成されます(進行中の会議は次回の同期で取り込まれます)。

## セットアップ手順(約10分・初回のみ)

1. [Google スプレッドシート](https://sheets.new) を新規作成し、名前を付ける(例: `Meet出席管理`)
2. メニュー **拡張機能 → Apps Script** を開く
3. エディタに表示されている `コード.gs` の中身を全て消し、この `Code.gs` の内容を貼り付けて保存
   (GitHub では「Raw」ボタンで開いてから全選択コピーすると確実です)
4. エディタ左側の歯車アイコン **「プロジェクトの設定」** を開き、
   **「『appsscript.json』マニフェスト ファイルをエディタで表示する」にチェック** を入れる
5. 左側の **「エディタ」(< > アイコン)** に戻ると `appsscript.json` というファイルが
   表示されるので、中身を全て消してこのフォルダの `appsscript.json` の内容を貼り付けて保存
   (Meet の参加記録を読むための権限をスクリプトに宣言する設定です)
6. **Google Cloud プロジェクトを作成して Meet API を有効化する**(初回のみ・無料):
   1. https://console.cloud.google.com に運用アカウントでログイン
      (初回は利用規約への同意画面が出ます。請求先・クレジットカードの登録は不要です)
      ※ Google Cloud の利用には Google アカウントの **2段階認証(MFA)** の設定が必須です
      (2026年4月〜)。「Google Cloud へのアクセスがブロックされました」と出た場合は、
      画面の「MFA を有効にする」から2段階認証を設定 → 1分ほど待ってページを再読み込み
      してください。
   2. 画面上部のプロジェクト選択 → **「新しいプロジェクト」** → 名前(例: `meet-attendance`)を
      付けて **作成** し、作成したプロジェクトを選択する
   3. メニュー **「APIとサービス」→「ライブラリ」** → `Google Meet API` を検索 → **「有効にする」**
   4. **「APIとサービス」→「OAuth 同意画面」**(Google Auth Platform の画面が開く)→
      **「開始」** をクリック → アプリ名(例: `Meet出席管理`)とサポートメールを入力 →
      対象は **「外部」**(選択肢が表示されない場合は自動で外部になるのでそのまま進む)→
      連絡先メールを入力 → 同意にチェックして **「作成」**
   5. 作成後、左メニューの **「対象」(Audience)** → 「テストユーザー」の **「+ Add users」** で
      **運用アカウントのメールアドレスを追加**
   6. **「IAMと管理」→「設定」** で **プロジェクト番号** をコピー
   7. Apps Script の **「プロジェクトの設定」→「Google Cloud Platform(GCP)プロジェクト」→
      「プロジェクトを変更」** → プロジェクト番号を貼り付けて **「プロジェクトを設定」**
7. `コード.gs` を開き、上部の関数選択で `syncAttendance` を選び **実行** →「承認が必要です」と
   出るので、会議を主催しているアカウントで **許可** する
   (「このアプリは Google で確認されていません」と出た場合は「詳細」→「(プロジェクト名)に移動」)
8. 実行が終わるとシートに過去90日分の参加記録と集計が入ります
9. 最後に関数 `setupDailyTrigger` を一度実行 → **毎日15時台に自動同期**されるようになります
   (時刻は `Code.gs` の `CONFIG.TRIGGER_HOUR` で変更できます。変更後は
   `setupDailyTrigger` を再実行してください)

以降は何もしなくても、スプレッドシートを開けば最新の出席状況と月次集計が見られます。

## 日常の使い方

スプレッドシートを開くとメニューバーに **「Meet出席」** が追加されます。

- **今すぐ同期** — 会議直後などに手動で最新データを取り込みたいとき
- **集計だけ更新** — 名前対応表を編集した後などに集計へ反映したいとき
- **報告文を作成(最新回)** — 最新の開催回の出席データから Chatwork 共有用の
  報告文の下書きを生成(下記参照)
- **アンケート結果をまとめる(月次)** — Google フォームの回答を月ごとに集計して
  フィードバック文の下書きを生成(下記参照)
- **毎日の自動同期を設定** — トリガーの再設定

### Chatwork 報告文の自動生成

メニュー **「報告文を作成(最新回)」** をクリックすると、最新の開催日の出席データから
報告文の下書きがポップアップで表示されます。「全文をコピー」ボタンでコピーし、
「内容」と資料の URL だけ埋めて Chatwork に貼り付けてください。

- 参加者名が「宮村(大阪)」のように **名前(拠点)** の形式になっていれば、
  拠点ごとの名簿(大阪:◯◯、◯◯ / 東京:◯◯)を自動で作ります
- 時間は最初の入室〜最後の退出から自動算出します
- 冒頭のあいさつ・アンケートURL・名簿から除外する名前(運営アカウントなど)は
  `Code.gs` の `CONFIG`(`REPORT_HEADER` / `REPORT_SURVEY_URL` / `REPORT_EXCLUDE`)で
  変更できます

### アンケート結果の月次集計

メニュー **「アンケート結果をまとめる(月次)」** で、Google フォームの回答を月ごとに
集計したフィードバック文を生成します。プログラムチャットへの共有用です。

**回答データの場所:** 既存の回答スプレッドシートの URL を
`Code.gs` の `CONFIG.SURVEY_SPREADSHEET_URL` に設定します。読み取り方法は2通りです。

1. **取込シート方式(推奨・権限変更不要)**
   メニュー **「アンケート取込シートを作成」** を実行すると、`IMPORTRANGE` で
   回答をミラーする「アンケート回答(取込)」シートが作られます。初回のみ
   A1セルの **「アクセスを許可」** をクリックしてください。以降は自動で最新化されます。
2. **直接読み取り方式**
   `appsscript.json` のスコープを `spreadsheets.currentonly` から `spreadsheets` に
   変更して再承認すると、別ファイルを直接開いて読みます。
   権限が足りない場合は自動的に 1 の取込シートを探しにいきます。

回答シートは「タイムスタンプ」列を持つシートを自動判別します
(`CONFIG.SURVEY_SHEET` で明示指定も可)。取り込み元のタブを指定したい場合は
`CONFIG.SURVEY_SOURCE_TAB` にタブ名を設定してください。

接続状況は `checkSurveyAccess` を実行すると実行ログで確認できます。

**使い方:** メニューをクリック → 集計したい月を `YYYY-MM` で入力(空欄なら先月)→
生成された文章を「全文をコピー」してチャットに貼り付け。

設問の種類は回答内容から自動判別します。

- 5段階評価などの数値 → 平均点と分布(`5:8件 / 4:3件 …`)
- 選択肢 → 件数と割合
- 自由記述 → 箇条書きで列挙(既定で最大20件。`CONFIG.SURVEY_MAX_COMMENTS` で変更可)

## 参加者名を本名に置き換える(名前対応表)

Meet のアカウント名(表示名)が本名と違う参加者のために、「名前対応表」シートで
置き換えを管理できます。

**使い方:**

1. 同期が実行されるたびに、新しく参加した人が「名前対応表」に自動で1行ずつ追加されます
   (A列: 参加者キー、B列: Meetでの表示名、C列: 空欄)
2. C列 **「正式な名前(ここに入力)」** に本名を入力する
3. メニュー **「Meet出席」→「集計だけ更新」** を実行する(次回の自動同期でも反映されます)
   → 参加ログと参加者マスタの名前が本名に置き換わります

**ポイント:**

- 本名が未入力の人は Meet の表示名のまま表示されます(入力は任意・後からでもOK)
- **同じ本名を入力した行は同一人物として統合されます。** ログインせずに参加して
  表示名が毎回違う人でも、それぞれの行に同じ本名を入力すれば、参加回数や
  リピート率が正しく計算されます
- 同姓同名の別人がいる場合は「山田太郎(A)」「山田太郎(B)」のように区別して入力してください
- 今後、新しい参加者が来たら C列を埋めるだけ。修正したいときは C列を書き換えて
  「集計だけ更新」を実行するだけです

## 設定のカスタマイズ

`Code.gs` 冒頭の `CONFIG` で変更できます。

```js
const CONFIG = {
  LOOKBACK_DAYS: 90,                  // 初回同期で遡る日数
  // 集計対象の会議コード(複数指定可)。[] にすると主催した全会議が対象
  MEETING_CODES: ['fnu-guox-pfg', 'ust-ndqc-kwk'],
  MIN_MINUTES: 0,                     // 例: 10 にすると10分未満の滞在は出席にカウントしない
};
```

会議コードは Meet の URL 末尾(`https://meet.google.com/fnu-guox-pfg` の `fnu-guox-pfg`)です。
リンクを作り直したときは、新しいコードを `MEETING_CODES` に追加してください
(古いコードを残しておけば、過去の記録も引き続き集計対象になります)。

## トラブルシューティング

### 実行時に「Meet API へのアクセスが許可されていません (HTTP 403)」と出る

スクリプトに紐づく Google Cloud プロジェクトで Meet API が有効化されていません。
Meet API は Apps Script の「サービス」一覧・アドバンストサービスとして提供されて
いないため(「サービス(meet v2)が見つかりません」エラーになる)、
標準の Google Cloud プロジェクトを作成して紐づける必要があります(初回のみ・無料)。
上記「セットアップ手順」の **手順6** を実施してから、`syncAttendance` を再実行して
再度承認してください。

### 参加ログに同じ内容の行が重複している

同期が同時に複数回実行された場合(メニューの連続クリックや、自動同期と手動同期の
重なり)に発生していた事象です。現在は同時実行ロックで防止しており、既に重複して
しまった行も「今すぐ同期」または「集計だけ更新」を実行すると自動で削除されます。

### 貼り付け後に「SyntaxError: Unexpected end of input」と出る

コードが途中までしか貼り付けられていません。GitHub の「Raw」ボタンで開いてから
全選択コピーし、`コード.gs` を全削除してから貼り直してください。

## 注意点・制限事項

- **参加者の識別**: Google アカウントでログインして参加した人はアカウントIDで確実に
  同一人物として追跡されます。**ログインせず名前入力だけで参加した人は表示名で識別**する
  ため、「山田」「山田太郎」のような表記ゆれがあると別人としてカウントされます。
  → 参加者にはログインして参加してもらうのが確実です。表記ゆれが発生した場合は
  「名前対応表」で同じ本名を入力すれば同一人物として統合できます。
- **滞在時間**は「最初の入室〜最後の退出」で計算しています(途中退席して戻った場合、
  離席時間も含まれます)。
- 過去の会議データをどこまで遡れるかは Google 側の保持期間に依存します。
  導入後のデータは毎日取り込まれるため確実に蓄積されます。

## 参考: Google Workspace をお使いの場合の代替手段

Google Workspace(Business Standard 以上 / Education)には、会議終了後に主催者へ
出席レポート CSV がメールで届く「出席状況の確認」機能があります。ただし月次集計や
リピート率の計算は結局手作業になるため、その場合でも本ツールの併用をおすすめします。
