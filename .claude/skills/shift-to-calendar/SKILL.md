# シフト表 → Googleカレンダー反映

スタッフシフト表から対象者の1か月ぶんを抜き出し、Googleカレンダーに終日予定として登録する。
毎月のシフトが出たら「カレンダーに反映して」の一言で回るように作られている。

## 設定

この設定は毎回そのまま使う。変更したいときはこのセクションを書き換えれば次回から反映される。

| 項目 | 値 |
| --- | --- |
| シフト表 | Googleスプレッドシート `【就労】東京｜スタッフシフト`（ID `1nN16Un42zATqMNampuYEwyFJI-bR0sw4kGljDv9N0pA`） |
| 反映先カレンダー | `libe.skillupkobo.hateruma@gmail.com` |
| タイムゾーン | `Asia/Tokyo` |
| 対象者（シフト表の行名） | `みだい` |
| 説明欄（兼・同期マーカー） | `【就労】東京｜スタッフシフト より自動登録（N月シフト）` |
| 再実行時 | 同じ月の同マーカー付き予定を削除してから作り直す |

対象者が設定と違う人だとユーザーが言った場合は、その回だけその人を対象にする（設定は書き換えない）。
「全員分」と言われたときは下の「全員分を登録する場合」に従う。

## 登録ルール

| シートのセル | カレンダー |
| --- | --- |
| `事業所` `在宅` `VO` `VO(叶内)` `在宅/事業所` など | セルの文字をそのままタイトルに |
| `休` `公休` `振休` `代休` | `【私用】予定あり（終日返答遅くなります）` |
| `有` `有休` `有給` | 同上（出勤しない日なので休みと同じ扱い） |
| 空欄・グレー | **何も登録しない** |

共通の設定：

| 項目 | 値 |
| --- | --- |
| 終日 | `allDay: true` |
| 表示 | `AVAILABILITY_FREE`（予定なし） |
| 公開設定 | `visibility: "public"` |
| 色 | 指定しない（カレンダーの既定色） |
| 通知 | 指定しない（カレンダーの既定） |

終日予定を「予定あり」にすると、共有カレンダーで空き時間を探している人から
その日が丸一日埋まって見えてしまうので、休みも含めて `FREE` にしている。

休みであることをそのまま書かず `【私用】` としているのは、共有カレンダーに私生活の情報を
載せないための言い回し。ユーザーが別の文言を指定しない限りこのタイトルを変えない。

セルが改行で2行になっている場合（`事業所` の下に `プロ`、`VO` の下に `(叶内)` など）は、
注記を括弧に入れて1行にまとめる：`事業所（プロ）` `VO(叶内)`。
すでに括弧が付いている注記は二重括弧にせず、そのまま繋ぐ。

## 手順

### Step 1. シフト表を手に入れる

**まずスプレッドシートを試す。** 画像から目で読むより確実で速い。
列と日付の対応がCSVの並び順で保証されるので、読み違いの余地がほぼ無くなる。

```
mcp__Google_Drive__search_files  query: title contains 'スタッフシフト' and mimeType = 'application/vnd.google-apps.spreadsheet'
mcp__Google_Drive__download_file_content  fileId: <上のID>  exportMimeType: text/csv
```

CSVエクスポートは **先頭シートしか返らない**。
このシートは新しい月が先頭に来る運用なので、普通は目的の月が先頭にある。
先頭が違う月だった場合は、`read_file_content` でシート名の一覧を見て、
目的の月のシートが先頭に来ていないことをユーザーに伝え、画像をもらう。

スプレッドシートが見つからない・読めないときは画像を使う。画像も無ければ、
ここで止めて出してもらう。前月のシフトを使い回したり、記憶で補完したりしない。

画像が複数枚（前半・後半など）に分かれている場合は、1日から月末までが
どこかに必ず写っていることを先に確認する。

### Step 2. 日付ごとのセルを書き出す

対象者の行を、**その月の1日から末日まで1日も飛ばさずに** 読み取り、
スクラッチパッドにJSONで保存する。

```json
{
  "year": 2026,
  "month": 12,
  "person": "みだい",
  "expected_off_days": 9,
  "calendar_id": "libe.skillupkobo.hateruma@gmail.com",
  "days": [
    { "date": "2026-12-01", "weekday": "火", "cell": "事業所",   "action": "work" },
    { "date": "2026-12-02", "weekday": "水", "cell": "休",      "action": "off"  },
    { "date": "2026-12-04", "weekday": "金", "cell": "有",      "action": "off"  },
    { "date": "2026-12-06", "weekday": "日", "cell": "",        "action": "off"  },
    { "date": "2026-12-21", "weekday": "月", "cell": "VO(叶内)", "action": "work" }
  ]
}
```

- `weekday` は **計算した曜日ではなく、シフト表に書いてある曜日** をそのまま写す。
  計算値を入れると検算が素通りしてしまい、ズレを見つけるという唯一の目的が失われる。
- `cell` は見たままの文字。括弧書きもスラッシュも省略しない。空欄・グレーなら空文字。
- `action` は `休`・`有`・空欄なら `off`、それ以外は `work`。
- 月の全日を必ず入れる。飛ばした日があると、読み落としなのか本当に空欄なのか区別できない。
- `expected_off_days` はシート右端の休み日数カウント（`9日` など）。
  この列は `休`＋空欄の日数で、**有給は含まれない**。検算スクリプトもそう数える。

### Step 3. 検算する

```bash
python3 .claude/skills/shift-to-calendar/scripts/validate_shifts.py <JSONのパス>
```

曜日の不一致・日付の重複や抜け・月外の日付・休み日数の不一致を検出する。
エラーが出たら、それは読み取りミスであってスクリプトの誤りではない。直してから進む。

曜日チェックは「列が1つズレている」を捕まえ、休み日数チェックは
「勤務日と休みを取り違えた」を捕まえる。別々の失敗を別々に見ているので、両方通す。

### Step 4. ユーザーに確認を取る

登録内容を表にして見せ、了承を得てから書き込む。他人と共有しているカレンダーなので、
勝手に確定させない。勤務日の一覧と内訳、休みの日付、登録しない空欄の日付を並べる。
読み取りに自信がないセルがあれば、その日付を名指しで伝える。

ユーザーが明示的に「作成して」と言っていて、確認すべき点を事前に解消済みなら、
一覧を見せたうえでそのまま作成に進んでよい。再実行で作り直せるので取り返しはつく。

### Step 5. 既存の同期済み予定を消す

同じ月を何度反映しても増殖しないように、先に前回ぶんを消す。

1. `mcp__Google_Calendar__list_events` で対象カレンダーの対象月を取得する
   （`startTime` は月初、`endTime` は翌月初、`timeZone` は `Asia/Tokyo`、`pageSize` は 250）。
2. 説明欄が `【就労】東京｜スタッフシフト より自動登録（N月シフト）` の予定だけを削除する。
3. この説明欄が無い予定は **絶対に消さない**。定例MTG・面談・レクチャーなど、
   ユーザーが手で入れた予定が同じ日に並んでいる。

削除した件数はあとで報告するので数えておく。

### Step 6. 予定を作る

「登録ルール」の表どおりに `mcp__Google_Calendar__create_event` を呼ぶ。
`startTime` はその日、`endTime` は **翌日**（終日予定の終端は排他的なので、
当日を入れると0日間になる）。独立した予定なので並列に呼んでよい。

### Step 7. 報告する

- 登録した件数（勤務日・休みの内訳つき）と対象月
- 削除した既存の同期予定の件数
- 判断に迷ったセルがあれば、その日付と理由

迷ったセルを黙って落とさない。勤務日が1日抜けるのは本人にとって実害がある。

## 全員分を登録する場合

「全員分」と言われたときは、表に載っている全スタッフを登録する。基本は同じで、次が変わる。

| 項目 | 全員分のとき |
| --- | --- |
| タイトル | `名前：セルの文字`（例 `つむり：事業所` `Knight：VO（戸田）`） |
| 休み | 登録しない（勤務日だけ） |
| 説明欄 | `【就労】東京｜スタッフシフト より自動登録（N月シフト・全員）` |

名前を頭に付けるのは、1日に6人ぶんの予定が並ぶので、誰の予定かがタイトルの先頭で
読み取れないと一覧として役に立たないため。

休みを登録しないのは件数の問題。6人×31日を全部入れると月186件になり、
カレンダーが埋まって肝心の「誰が出ているか」が読み取れなくなる。
勤務日だけなら月130件ほどで、その日に名前が無い人が休みだと分かる。

説明欄を分けておくのが大事で、これが同じだと、ひとり分を作り直したときに
全員分まで巻き添えで消える。削除するときは説明欄を完全一致で見る。

JSONは `person` / `days` の代わりに `people` を使う。中身は同じ形。

```json
{
  "year": 2026, "month": 12, "calendar_id": "...",
  "people": [
    { "name": "つむり", "expected_off_days": 9, "days": [ ... ] },
    { "name": "タキ",   "expected_off_days": 9, "days": [ ... ] }
  ]
}
```

## つまずきやすいところ

- **CSVは先頭シートだけ**：目的の月が先頭でないときに気づかず前月を登録してしまう。
  CSVの1〜2行目に出る年月を必ず確認してから進む。
- **空欄とグレーの意味**：このシートでは「未定」ではなく休み。ただしカレンダーには
  何も登録しない運用なので、`off` として記録はするが予定は作らない。
- **有給は集計列に入らない**：シート右端の休み日数は `休`＋空欄だけ。
  有給を混ぜて数えると件数が合わずエラーになる。
- **画像が前半・後半に分かれている**：境目の日付が重複したり抜けたりする。
  日付単位で突き合わせれば重複は解消でき、検算の「抜け」エラーが撮り漏れを教えてくれる。
- **知らない記号**：勝手に解釈せずユーザーに意味を聞く。分かったらこの文書に追記する。
