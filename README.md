# 清掃予約管理

原状回復清掃の依頼を、**メール本文の貼り付けから LINE での配車・完了報告まで**ひと続きで扱うアプリです。

クライアントから届く依頼メールは、1 通に複数居室・居室ごとに違う期限と清掃内容が
混ざっています。これを人手で表に起こす作業をなくすのが目的です。

```
231・233・308・322・338号室
【時期】338号室→至急 / 233・308・322号室→9月中 / 231号室→なるべく早めに
【清掃内容】231・233・308・322号室→通常の清掃のみ / 338号室→プラス剥離
```

↓ 貼り付けるだけで

| 部屋 | 緊急度 | 期限 | 清掃内容 |
| --- | --- | --- | --- |
| 338 | 至急 | 2026-09-22 | 通常清掃・剥離・原状回復 |
| 231 | 早め | 2026-10-03 | 通常清掃・原状回復 |
| 233 / 308 / 322 | 通常 | 2026-09-30 | 通常清掃・原状回復 |

## 画面

| パス | 用途 |
| --- | --- |
| `/` | ダッシュボード。期限超過・至急・未割当をひと目で |
| `/intake` | 依頼メールの貼り付け → 解析 → 修正 → 一括登録 |
| `/board` | 案件ボード。担当割当・実施予定日・状態変更・スタッフ管理 |
| `/liff` | スタッフ用のスマホ画面。自分の担当と未割当案件 |
| `/todo` | 以前からの ToDo リスト |

## LINE でできること

LINE 公式アカウント（Messaging API）を設定すると次が動きます。設定手順は
[`docs/LINE_SETUP.md`](docs/LINE_SETUP.md)。**未設定でも Web 画面だけで運用できます。**

- **配車**: 案件登録と同時に、スタッフのグループへ案件カードを送信
- **受諾・進捗・完了報告**: カードのボタンを押すだけ（`受ける` → `作業開始` → `完了報告`）
- **問い合わせ**: スタッフが `一覧` `今日` `担当` と送ると該当案件が返る
- **依頼の受付**: 依頼元が LINE に依頼文を送ると、メールと同じ解析で案件登録

## 依頼文の読み取り仕様

`src/lib/parser.ts` が担当します。

- 全角数字・`⇒` `=>` `->` などの表記ゆれを吸収
- `231・233・308・322・338号室` のような並びを居室ごとに展開（`以上5居室` は数え上げとして除外）
- 期限: `至急`（+3日）/ `なるべく早め`（+14日）/ `9月中`（月末）/ `10月上旬`（10日）/ `10月5日` / `今月末` / `来週` など
- 清掃内容: `通常の清掃のみ` → 通常清掃、`プラス剥離` → 通常清掃 + 剥離（加算表現を解釈）
- 居室ごとの指示が本文全体の指示より優先
- メール記載の居室数（`以上5居室`）と読み取り件数が食い違えば警告

読み取った結果は登録前に `/intake` 画面で必ず修正できます。

## 開発

```bash
bun install
cp .env.example .env.local   # LINE を使う場合のみ編集
bun run dev                  # http://localhost:3000
bun test                     # パーサーと案件サービスのテスト
bun run lint
bun run build
```

## データの保存先

`data/db.json`（`DATA_DIR` で変更可）に JSON で保存します。単一プロセス前提の簡易ストアです。
複数インスタンスで動かす場合は `src/lib/store.ts` を DB 実装に差し替えてください。
読み書きは `read()` / `write()` の 2 つに集約してあります。
